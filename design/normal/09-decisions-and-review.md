# 变更与多Agent评审

日期：2026-10-23。本次以用户粘贴的普通方案为实施依据。设计确认不等于生产完成。

| 决定 | 理由与影响 |
|---|---|
| 普通6区×9关，56小时预算 | 替代此前区域过少与普通过短的候选；55—65小时仍待真实模型与试玩 |
| 两名主力+辅助供料为基准 | 防止通过强迫培养全员虚增时长 |
| 本体招募约10—12小时目标 | 零延迟9h50计算不能直接当开局墙钟；真实来源1-2开放 |
| 双纹章槽移至3-9后 | 普通延长后让双槽在主线里发挥作用；3-9仍必须单槽可通 |
| 装备使用与精炼同时受区域许可 | 允许提前收藏，防止跨区装备和早期装备无限精炼绕过成长 |
| 基础纹章配方节点细化 | 1-3创伤、1-4守护、1-8蓄能、2-2净化、2-4猎印、2-6余烬，作为原型默认 |
| 通用功能装备模板 | 本次细化：同一件实体适配角色本职武器外观，降低掉落池与动作制作成本；实体仍唯一占用 |
| 同区三件备用装备+同区触媒定向交换 | 本次细化：禁止低区输入换高区输出造成套利；绑定/未绑定配方分离 |
| 未绑定交换作为收藏操作 | 可提前交易/交换收藏；Steam配方编码同区输入，不能假定平台客户端交换受自定义后端区域许可拦截，使用和精炼才检查区域许可 |
| 稀有目标在整趟结束或放弃后切换 | 与三场成功才确认资格一致，避免中途把别队时间转入更有利池 |
| 回访例子改为已首通3-8、挑战3-9 | 原例3-5未过却刷3-6存在顺序矛盾，修正叙述不改变解锁 |
| Unity原型固定6000.6.5f1 | 实际安装且能创建工程，不更换引擎、不自动升级工具 |

## 分工与审查边界

- 玩法Agent编写地图、36个普通/精英/Boss模板与54关数据。
- 数值Agent编写预算模型、检查器、坏数据测试，并实现原型领域逻辑。
- Steam/窗口Agent编写装备交易、三窗规则和24模板，交叉审查资产、时钟与前置。
- 主Agent整合角色、技能、循环、Unity表现与构建，修复跨文件矛盾并执行验证。

本次是真实分工和交叉检查，不等同陌生玩家体验评审或Steam平台认证。最终执行结果、剩余问题与证据见[验证记录](../../production/qa/normal-campaign-validation.md)。

## 实现后的第二轮交叉审查

| 发现 | 已落实修正 | 证据范围 |
|---|---|---|
| Stop/Start和移动成员可跳过休整 | 恢复截止时间同时关联队伍与角色；主动败退30秒，已有休整不清零 | Unity领域回归、Steam/窗口Agent复审 |
| 曾通过的当前关可能成为三败回退目标 | 撤销当前安全记录，仅退更早、空闲且配置验证过的关卡 | Unity故障注入 |
| 换人会自动移走另一队成员 | 显式卸下，拒绝抢占；恢复期也不可转队绕过 | Unity领域回归 |
| 低帧率丢时间、加速积压被新配置追认 | 保留积压；未清空前禁改队/派遣，保留降速和暂停 | 时钟回归、玩法Agent源码复审 |
| 摘要背景仍可操作，拒绝提示在小屏外 | 阻断背景操作；通知固定视口，配置用滚动访问 | 源码修正、实际Player画面检查；真人点击体验待测 |
| 基础纹章开局全部可选 | 开局空槽，按既定配方节点开放，3-9后第二槽 | Unity领域回归 |
| 摘要只有静态免责声明 | 显示账号进展、各队结果、最近失败和稀有资格 | 实际运行摘要 |
| 时间数字格式会显示错误数字 | 使用小数占位格式；导出原始秒数区分真实与模拟 | 代码检查与Player显示 |
| 回访示例与自动保留打断行为不一致 | 改为盾护提前释放、钟击时在冷却，并用蓄力条件解决 | 文档一致性修正 |

审查后的Unity构建和自动检查通过不等于游戏体验通过；人工玩法结论保持 NOT ASSESSED。

## 尚未满足的发行条件

没有完整的配方/产率驱动56小时闭环；没有真实50小时试玩；原型没有生产存档、离线经济或全部装备/纹章效果；没有可靠市场后端与Steam实际应用验收。不得据此推进正式大量资产制作或宣称市场经济稳定。
