# 原型、数值检查与真实试玩

## 本轮交付边界

本轮交付普通设计、结构化数据、可复算检查与Unity占位机制原型。正式美术、完整商业后端、Steam应用市场批准、50小时人工体验不能由本地实现冒充完成。验证实际状态见[本次证据](../../production/qa/normal-campaign-validation.md)。

## 三个危险假设

| 假设 | 最小实验 | 观察指标与失败信号 |
|---|---|---|
| 玩家愿意在回访时作配置决定 | 第一章九关，至少两组目标玩家观察；不给答案，让玩家解释失败并重试 | 能否指出主要威胁、主动改变条件/搭档、重试后解释结果；反复只点升级为失败信号 |
| 自给两主力路线能支撑55—65小时 | 建真实配方/产率/敌人强度表后，模拟集中培养；再做完整时间试玩 | 首通分布、各区停滞、无有用结果空窗；不能靠强迫养满角色或时钟门槛补时 |
| 三队可看懂且不会三倍管理 | 同屏3队各2人最多3敌，包含不同威胁；折叠/切换/回访实操 | 能否快速指出哪队失败及原因，是否漏掉稀有资格说明；一窗可读不算通过 |

人数、阈值和时间窗口用于制定实验，不把未进行的调查写成研究结论。第一轮可先招募5—8名熟悉挂机游戏的玩家；发现共同理解障碍后修订，再扩大样本，不能据此宣称代表多数Steam玩家。

## 自动检查可以回答什么

- 六区54关、每关三场、前置无跳跃/死锁、5/9末场类型、敌人引用及数量上限。
- 角色资格、开队人数和通关条件、第三技能和第二纹章槽解锁可达。
- 稀有模板24、每区四项等权、5/7/9同池、装备绑定和使用许可字段。
- 线性成长锚点、预算合计、招募分析的启动延迟、带保底的稀有期望。
- 核心运行中的占用冲突、失败保留普通奖励、完整通关才提交资格、配置变更使安全记录失效。

自动检查不能回答是否好玩、50小时是否耐玩、市场物品是否有价格、真实后端能否抗作弊、玩家能否理解界面。`NOT_VALIDATED`不是错误退出码的同义词，而是明确缺乏对应证据。

## 下一轮完整数值模型所需输入

逐关记录每种材料与装备的产率、主力必需配方的净缺口、辅助队最低成本、升级成功后的通关耗时、失败率、真实技能覆盖率。固定分工下按最慢资源瓶颈计算，多个同时掉落不能相加；跨队供料和招募分流必须入账。

比较六种路线：两名主力集中培养；平均养六人；暂缓招募；允许当前区域市场购入；有限离线基础补给；优先DLC招募。普通目标以第一种自给路线为基准，其他路线不强行锁到同一时长。

## 人工验收矩阵

| 场景 | 条件 | 需要观察 |
|---|---|---|
| 前30分钟 | 新档、两人一队、无市场 | 能理解自动探索并设置下一轮目标 |
| 第一区精英/Boss | 至少两套本体组合 | 打断或防护/集火均有通过路径 |
| 3-9 | 单纹章槽、普通装 | 不需要尚未解锁的第二槽 |
| 4-1 | 新开放双槽 | 玩家能看出组合产生的变化 |
| 5-5 | 含净化/无专职治疗两路线 | 不形成永久迟缓或指定角色钥匙 |
| 三队重试 | 一队失败、两队刷取 | 不抢占他队关卡、资产或单位 |
| 6-9 | 无DLC/无稀有必需品 | 完整结局、通关后继续刷取，资产保留 |
| 第10/20/35/50小时回访 | 真实时间与加速时间分开 | 仍有明确目标与有意义选择，记录疲劳原因 |

每场试玩保留版本/数据hash、路线、真实在线时长、模拟加速时长、离线补给、市场购入、DLC、失败原因、配置变化与口述。不得把模拟日志写成玩家发言。
