# 普通难度：三队同窗探索与回访体验

版本：设计草案 v0.1；更新：2026-10-23。此处“小窗”指一个主窗口内的队伍区域，不指三个独立操作系统窗口。

## 1. 体验目标与范围

玩家能同时看见各队在做什么，也能安心切换到其他工作。回访时先看到目标推进、需要处理的失败和值得比较的物品，再决定下一段探索。长期目标是每 30—60 分钟回访一次、用 2—5 分钟完成主要管理；这些是待试玩验证的目标，不是已经测得的使用节奏或强制登录间隔。

- 开局只有一支两人队伍；已开放并派出的队伍区域默认展开。随着进度最多显示三队，不能在开局伪装成三队可用。
- 三个区域可以同时展开，各自独立收起；收起只停止该区域的渲染，不暂停战斗、冷却或产出。
- 每队最多两名角色、三名敌人，同时三队最多六名角色、九名敌人。能攻击或受击的召唤单位也计入对应上限；装饰特效不能伪装成额外战斗单位。
- 六区九关是内容规模，运行时仍只有当前三处遭遇需要展示，不加载 54 个完整场景来维持后台探索。
- 战斗小人为日式幻想手绘 Q 版，角色管理页使用完整立绘。武器和盾牌保留有限外观变化，服装不做全身装备换装。

## 2. 一个主窗口的界面结构

原型默认使用纵向排列的三条横向战斗区域，方便同时比较不同关卡。具体像素尺寸随可读性验证调整，不在当前阶段锁定一套未经实测的窗口分辨率。

| 区域 | 常驻内容 | 操作用途 |
| --- | --- | --- |
| 全局目标条 | 当前招募／升级目标、材料进度、在线状态 | 让玩家知道现在在等待什么 |
| 队伍标题条 | 两人头像、地区与节点、遭遇 1／3、运行状态 | 展开收起、查看队伍、选择任务 |
| 队伍战斗区 | 小人、敌人、关键状态与威胁预告 | 解释战斗为何成功或失败 |
| 队伍摘要条 | 普通收获、成功率摘要、退路与寻获资格 | 快速找到需要调整的队伍 |
| 全局回访栏 | 本次离开以来的进展、异常和重要掉落 | 一次处理主要事项，避免逐页收取 |
| 管理入口 | 角色、装备技能、地图、炼制、收藏与交易 | 完成出发前准备与回访决策 |

已经开放的三队都展开时不能互相遮挡；打开角色详情应使用可关闭的侧栏或独立管理页面，并保持探索继续。窄窗口可进入紧凑布局，但不能默默暂停未显示的队伍。展开、收起和窗口大小属于观看偏好，不属于产出策略。

原型至少验证 1280×720 与 1920×1080、常见系统缩放和不同文字长度。验收关注三队名称、目标、威胁和运行状态能否读清，而不是只检查截图是否“放得下”。

## 3. 战斗观看与信息分级

每个节点有三场遭遇；第 5 和第 9 节点的第三场分别为精英与 Boss。节点标题、遭遇序号和进度必须分开显示，避免把“第 5 关”误读为“第五波”。

### 必须在小尺寸下辨认的内容

- 两位角色不同的轮廓、武器和主色；不只用颜色区分角色或状态。
- 敌人蓄力、护盾、持续伤害、减速、复起等当前关卡的关键问题；只显示会影响当前选择的信息。
- 角色正在使用的关键技能及其作用目标，队友保护需要有明确的来源与去向。
- 胜利、战败、换场、休整和转为离线基础收益之间的状态差别。

普通攻击采用简洁反馈，浮字可关闭或合并。重大威胁用图标、短文字与清楚的动作共同提示，不能只靠红绿色或一闪而过的粒子。战报记录关键事件与失败原因，玩家不用盯着全程才能理解问题。

统一音效总线管理三队：默认降低重复攻击声的密度，突出目标完成、重要威胁、战败和稀有收获。提供总静音、后台静音和重要通知开关，不让三队各自争抢通知音量。这里的聚合不改变战斗事件本身。

## 4. 出发、失败与退路

1. 玩家选择队伍、配置和关卡；同一角色或装备实例不能同时存在于两支出征队伍。
2. 选择的关卡若被另一队占用，出发入口显示冲突和占用队伍，不暗中派去另一关。
3. 展示本关主要威胁、材料／装备倾向和当前队伍配置；自动战斗开始后不要求玩家反复点击释放技能。
4. 每场按统一战斗规则结束并结算；战后恢复规则通过状态与战报说明，不能用没有标注的消耗品扣款实现恢复。
5. 战败显示最相关原因、已保留普通收获和本趟未确认的市场时间。主装备和角色保留，失败成本主要为时间。
6. 需要退回稳定节点时，若退路已被另一队占用，则进入休整并提示处理；不能把两队塞入同关，也不能继续显示原关卡的寻获资格。

回访界面允许“查看原因 → 比较一件装备或调整一个技能 → 再试一次”，并保留队伍预设，减少重复配置操作。不能把一键推荐包装成已证明的最优解。

## 5. 稀有寻获界面

每次只指定一支寻获目标队；其他两队的探索画面继续正常显示。指定标记既出现在全局目标条，也出现在该队标题条。

| 状态 | 玩家看到什么 | 规则含义 |
| --- | --- | --- |
| 尚未满足资格 | 当前关卡不累计；提示可用节点条件 | 第 1—4、6、8 关不计市场时间 |
| 合格探索进行中 | 本趟待确认时间、遭遇进度 | 完成第三场之前尚未入账 |
| 已确认计时 | 对应地区普通桶的已累计时间 | 每满 15 分钟进行一次账号判定 |
| 未中奖 | 已增加的普通档保底进度 | 不是物品丢失，也不是必须马上再点一次 |
| 获得稀有 | 确定的装备或触媒、去向与状态 | 四类等权；触媒也重置稀有保底 |
| 已登记待送达 | 明确显示待同步，可查看记录 | 平台暂不可达不能把它显示成永久丢失 |

说明中应同时写明候选 10% 判定概率、20 次任意稀有保底、四类物品各 25% 的条件概率。不能用“15 分钟必得稀有”“五小时必得指定武器”等文案。

切换地区时显示该地区已保存的部分时间；不把旧地区进度条直接挪到新地区。更换目标队在当前整趟关卡完成或主动放弃后生效，客户端立即给出“将在本趟关卡结束后切换”的反馈；主动放弃时说明未完成趟不计市场时间。新目标从下一趟完整关卡开始累计。三队共用一份时间，不通过额外开窗、加快动画或点开掉落界面增加判定机会。

## 6. 装备比较、绑定与交易反馈

装备详情按“当前装备／候选装备”展示基础属性、条件效果与限制。候选特效未填完数值前，原型应标注占位数据，不能把示意值误写成已平衡数据。

首次使用未绑定稀有装备时显示：

- 当前所有权和来源区使用许可是否满足；不满足时解释原因。
- “确认后成为个人永久装备，不能再次交易”的完整说明。
- 将替换哪名角色的哪个栏位，以及旧装备会回到哪里。
- 明确的“绑定并装备”按钮；预览、比较和收藏不触发绑定。

提交后显示“处理中”，并阻止同一实例被本服务重复绑定或参与另一配方。响应未知不显示成功动画，不诱导玩家再次支付。成功通知可恢复送达；只有可信确认后，角色实际战力与小人武器表现才更新。

市场入口显示物品当前是否可售、是否已有平台限制，并引导使用 Steam 提供的交易页面。不得声称可以提现、保证出售价格或保证立即成交。库存内的已绑定物应持续标识“个人装备”，不可在交易筛选中混入。

## 7. 回访候选旅程

中期离开一小时后，玩家回来先看到：目标材料推进多少、哪支队伍需要处理、是否有重要装备或稀有物。一次候选回访如下：

1. 查看汇总：两队稳定、一队在精英末场失败；前两场普通奖励已经保留，失败趟不增加市场资格时间。
2. 打开该队战报，发现护盾处理效率不足；比较刚得到的普通装备和一个候选纹章配置。
3. 决定继续准备招募材料，或花材料改善当前组合；确认一项调整后重新安排目标关卡。
4. 查看指定寻获队的地区桶与保底状态，然后再次离开。

该例只解释需要的信息和决策，不保证一小时内出现升级、稀有物或足够招募材料。验证目标是玩家能用 2—5 分钟处理主要决定，而不是被迫把全部物品和三队菜单检查一遍。

## 8. 呈现与可信模拟的接口边界

呈现只消费可信战斗事件及持久结果快照，不以动画完成、窗口可见或本机 `deltaTime` 决定发奖。事件至少需要能区分队伍、关卡、遭遇、序号、发生时间和结果版本；具体协议在技术设计阶段确定。

Unity 6 可将摄像机输出到 RenderTexture，再显示在队伍区域，这是三视图的常规候选路径。官方文档描述渲染能力，不代表本项目已经完成性能验证。[Camera.targetTexture](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Camera-targetTexture.html)

后台降帧和折叠可以减少绘制；可信模拟继续按规则推进。系统睡眠、进程退出和网络资格失效需要进入基础离线流程。恢复时重新取得快照，播放简洁摘要，不靠快速补播积压动画生成“离线稀有”。

## 9. 可用性与正确性验收

| 检查 | 观察与通过条件 |
| --- | --- |
| 三队默认展开 | 能同时辨认每队角色、目标、遭遇序号和状态；无界面互相遮挡 |
| 相同战斗种子与在线时长 | 全展开、全折叠、后台降帧的持久结果一致 |
| 第三场失败 | 普通奖保留、市场时间不确认，界面解释一致 |
| 切换寻获目标 | 仅一队计时，区域部分进度不丢失、不转池、不重叠 |
| 绑定响应丢失 | 显示处理中；重新打开界面不会生成第二件装备 |
| 退路被占用 | 明确休整和冲突原因，不违反同关排他规则 |
| 颜色、声音关闭 | 关键威胁仍有图标与文字，通知不会完全失去含义 |
| 一小时回访 | 观察是否能找到最值得处理的一件事，记录实际管理耗时和无意义操作 |
| 不看小窗 | 通过战报仍能理解关键失败；持续观看只增加观察乐趣，不增加奖励 |
| 睡眠、断线、重连 | 不补算无资格的稀有时间；已登记待送达奖励可恢复 |

当前只交付 UX 规则与候选旅程。没有完成 Unity 画面、性能测试或目标玩家可用性测试；来源核验日期为 2026-10-23。
